## 1. Andrej Karpathy: From Vibe Coding to Agentic Engineering

**🎬** https://www.youtube.com/watch?v=96jN2OCOfLs
**👤 Auteur** — AI Ascent (Stephanie Zhan)
**🇬🇧 Title** — Andrej Karpathy: From Vibe Coding to Agentic Engineering w/ Stephanie Zhan
**🇫🇷 Titre** — Andrej Karpathy : du Vibe Coding à l'Engineering Agentic

### Chapitres

| Timestamp | Section |
|-----------|---------|
| 00:00 | Introduction — Présentation d'Andrej Karpathy |
| 00:44 | Feeling Behind as a Coder — "Je ne me suis jamais senti aussi en retard comme programmeur" |
| 02:28 | Software 3.0 Explained — LLM comme nouvelle machine informatique |
| 03:44 | Agents as the Installer — OpenClaw : copier-coller un texte vers son agent |
| 07:37 | What's Obvious by 2026 — Ce qui sera évident en rétrospective |
| 09:41 | Verifiability and Jagged Skills — Vérifiabilité et compétences inégales |
| 15:46 | From Vibe Coding to Agent Engineering — Transition vers l'ingénierie agentique |

### Résumé

Andrej Karpathy, co-fondateur d'OpenAI et ancien responsable de l'IA chez Tesla, explique sa transition fulgurante vers le "vibe coding" à partir de décembre 2025. Il décrit le passage du Software 1.0 (code explicite) et Software 2.0 (réseaux neuronaux entraînés) au Software 3.0, où le programming se fait par prompting et le contenu de la fenêtre de contexte devient le levier sur l'interpréteur LLM. Il illustre ce paradigme avec deux exemples frappants : l'installation d'OpenClaw via un simple texte à copier-coller donné à un agent (au lieu d'un script shell complexe), et MenuGen, une application qu'il a construite pour visualiser des menus restaurant — qu'il considère désormais comme "spurious" car Gemini avec Nano Banana peut réaliser la même tâche en une seule image prompt sans aucune application intermédiaire. Karpathy prédit que les réseaux neuronaux deviendront le processus hôte et les CPU des coprocesseurs, inversant la hiérarchie computing de 70 ans.

### Citations notables

> "I think that a lot of people experienced AI last year as ChatGPT adjacent thing, but you really had to look again, because as of December things have changed fundamentally — especially on this agentic coherent workflow that really started to actually work."

> "What is the piece of text to copy-paste to your agent? That's the programming paradigm now."

> "There's new opportunities of just things that couldn't be possible before. And I almost think that that's more exciting [than making existing things faster]."

### Takeaways actionnables

- **Repensez vos instal scripts** : si un outil peut être installé par un agent intelligent via un texte, écrivez ce texte plutôt qu'un script shell complexe — c'est le Software 3.0.
- **Évaluez si votre application "devrait exister"** : les modèles multimodaux (Gemini + Nano Banana) peuvent remplacer des apps entières en une seule image-prompt.
- **Nouveaux horizons** : les LLM permettent de créer des wikis d'organisation, des bases de connaissances recompilées — des tâches informatiques impossibles avant car aucun code ne pouvait les réaliser.

### Résumé

AI Search présente GLM 5.3 de ZAI comme le nouveau numéro 1 open source, performant aussi bien que Claude Fable et les meilleurs modèles GPT sur plusieurs tâches. Le vidéo démo montre le modèle utilisé via le harnais "Z Code" (comparable à Claude Code ou Codeex) pour réaliser des tâches d'agentic coding à long horizon. Une seule prompt génère une réplique fonctionnelle de Windows 11 dans le navigateur (écran de connexion, paramètres, Office, Paint, Slack, Spotify, Store) en 22 minutes, avec plusieurs agents autonomes travaillant en parallèle sur les différentes applis. GLM 5.3 contrôle aussi Blender via MCP pour créer un moteur V8 animé en 3D avec plus de 100 composants, et développe un jeu de combat 3D en téléchargeant automatiquement des modèles depuis SketchFab et des animations depuis Mixamo.

### Citations notables

> "For most instances, it even matches the performance of Cloud Fable and the best GPT model."

> "It even takes a screenshot to test everything out and it found several bugs by itself and it's automatically fixing each one."

### Takeaways actionnables

- **Z Code comme harness** : disponible sur toutes les plateformes, similaire à Claude Code/Codeex — à tester pour vos workflows d'agentic coding.
- **Agents multi-tâches parallèles** : GLM 5.3 peut lancer des agents séparés pour construire simultanément des composants différents (Office, Discord, Explorer, Store) et les assembler.
- **Débogage autonome** : le modèle prend ses propres screenshots pour vérifier ses sorties et corrige les bugs sans intervention humaine.

## 4. The Real Reason Researchers Are Switching to Claude in 2026 (Projects, Skills, Cowork, Consensus)

**🎬** https://www.youtube.com/watch?v=QqNXf7DfSpA
**👤 Auteur** — AI Search
**🇬🇧 Title** — The Real Reason Researchers Are Switching to Claude in 2026 (Projects, Skills, Cowork, Consensus)
**🇫🇷 Titre** — La vraie raison pour laquelle les chercheurs passent à Claude en 2026

### Chapitres

| Timestamp | Section |
|-----------|---------|
| 00:00 | Intro — Claude comme LLM académique préféré |
| 01:00 | Projects — encapsulation de fichiers, instructions personnalisées, mémoire de projet |
| 03:00 | Connectors — intégration de Consensus et autres outils externes |
| 04:08 | Skills — tâches répétables capturées comme instructions réutilisables |
| 06:50 | Desktop app — CoWork, artefacts, planification |
| 07:25 | CoWork — agentic AI avec approbation humaine ou "skip all approvals" |
| 09:00 | Live demo — literature review sur "OPV devices" via Consensus + skill |

### Résumé

Ce vidéo explique pourquoi Claude est devenu le LLM favori des chercheurs académiques en 2026. La fonctionnalité clé est "Projects" : chaque projet encapsule des fichiers, des instructions personnalisées et une mémoire contextuelle, permettant des sorties académiques much more rigorous. Les "Connectors" permettent d'intégrer des outils externes comme Consensus (base de données scientifique) directement dans le chat. Les "Skills" capturent des workflows répétables (ex: "literature review helper") qui peuvent être importés et réutilisés. Le CoWork du desktop app transforme Claude en agentic AI capable de lancer plusieurs agents en parallèle pour collecter, écrire, reviewer et analyser — avec option de validation humaine à chaque étape ou exécution autonome complète. La demo montre une literature review sur des OPV devices générée automatiquement en quelques minutes.

### Citations notables

> "Projects are so very valuable because if you're working on a little project, like for a paper, for a grant application, for a literature review, whatever it is, you can create its own little project."

> "Connectors give you the ability to connect Claude to an outside app that you want to draw information in from. And for science and research, I highly recommend that you go and you select Consensus."

> "Co-work is an agentic AI. It will do multiple steps to get to your answer. It will spin out multiple agents to go and collect data, to write, to review, to analyze."

### Takeaways actionnables

- **Structurez vos travaux en Projects** : créez un projet par papier/grants/literature review avec fichiers et instructions — Claude garde le contexte.
- **Installez le connector Consensus** : pour toute recherche académique, cela donne un accès direct aux papers scientifiques depuis Claude.
- **Créez vos propres Skills** : quand vous identifiez un workflow répétitif (lit review, analyse de données), capturez-le comme Skill pour le réutiliser.
- **CoWork avec human-in-the-loop** : gardez les approbations manuelles pour les tâches critiques, utilisez "skip all" pour les tâches répétitives.

### Résumé

Moonshot AI a sorti Kimi K3, un modèle open source qui se compare aux meilleurs modèles fermés (GPT 5.6, Claude Fable) selon AI Search. Le modèle est conçu pour les longs horizons agentic workflows et s'utilise idéalement via son harnais natif "Kimi Code" (extension VS Code). Trois demos spectaculaires : (1) un simulateur de splash de liquide codé from scratch sans librairie externe, avec contrôle via webcam et mains, en 30 minutes et 2M+ tokens d'entrée ; (2) un moteur V8 animé dans Blender avec 100+ composants en 40 minutes et 17M tokens d'entrée ; (3) une vidéo complète d'analyse des résultats financiers NVIDIA (81,6M$ de revenue, +85% YoY) avec voix Gemini TTS, graphiques animés via HyperFrames, en une seule prompt. Kimi K3 est lent mais méticuleux — il planifie longuement, vérifie ses sorties, et corrige les erreurs de lui-même.

### Citations notables

> "Open-source AI is no longer a few months behind the closed frontier models. Today, we have a new open-source model which is just as good."

> "This is designed for multi-step long horizon agentic workflows. So, basically, tasks where it can autonomously use tools and keep doing stuff for multiple steps until it achieves your goal."

> "It used over 2 million input tokens and 46K output tokens. It's definitely slow. and plans for a long time, but it gets the job done."

### Takeaways actionnables

- **Kimi Code + VS Code** : installable via l'extension VS Code marketplace — permet de lancer des agents sur des projets locaux persistants.
- **Plan mode** : avant d'exécuter, Kimi K3 peut entrer en "plan mode" pour stratégiser sans exécuter — utile pour les tâches complexes.
- **Token cost awareness** : les tâches agentic longues consomment des millions de tokens (17M+ en entrée pour le moteur V8). Estimer le coût avant de lancer.
- **Comparabilité fermés/open** : Kimi K3 démontre que l'écart qualité open/closed continue de se réduire — à surveiller pour les décisions d'adoption.
